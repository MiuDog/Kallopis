# 筆記功能蒸餾索引

2026-09-11 使用者修訂：功能參考必須涵蓋 Notion 的所有筆記元件、Concepts 的手寫體驗與 Miro 的 Spatial 元件。外觀主要參考 Craft 官網。這取代僅用 Notist 與 K01–K09 代表完整範圍的做法；原有 K 編號保留為首批實作切片，不能作功能範圍上限。

## 狀態與完整性

狀態：已啟動官方文件盤點，尚未完成所有元件蒸餾。下列是研究分類，不代表全部已查證或已實作。完成盤點須逐一對照官方元件目錄、詳細文件、實際互動與平台差異；每個項目需要唯一 ID、來源日期、資料、事件、狀態、slot、semantic、平台、核心缺口與驗收。不能用一個「其他元件」項目代替未讀內容。

研究與實作範圍分開追蹤：所有指定類別均須盤點；若某項依賴產品服務或核心能力，明列歸屬、依賴與排期，不直接刪除。方案、付費限制與第三方品牌名稱不作 Kallopis 分類依據。

## Notion 展開規格

逐項表：[Notion 筆記元件契約](notion-note-components-spec.md)，目前編列 N01–N68，分開記錄來源證據與 Kallopis 設計。清單仍需補齊 provider、property editor 及平台實機核對，不能據此宣稱完整蒸餾已完成。

逐項蒸餾的清單至少包含：段落、H1–H3、待辦、無序／有序清單、摺疊、引用、提示、分隔線、子頁面、頁面連結、簡易表格、程式碼、圖片、音訊、影片、檔案、書籤、PDF／外部嵌入、公式、按鈕、麵包屑、目錄、人員／頁面提及、日期／提醒與 emoji。這些初始分類依上方官方編輯文件；資料庫視圖與其他進階類型需從專屬頁面補齊，不宣稱此列已完整。

每個區塊還要檢查建立、轉換、複製、刪除、移動、巢狀、選取、拖曳、剪貼、快捷、空狀態、唯讀、錯誤、撤銷與無障礙。行內格式與區塊類型分開建模，不能將其全變成不同容器。

## Concepts 展開規格

逐項表：[Concepts 手寫體驗契約](concepts-handwriting-spec.md)，C01–C25。含輸入、筆跡、選取、圖層、精準輔助及中斷；平台實機與核心能力仍待驗證。

以手寫的完整生命週期蒸餾：裝置辨識→落筆→取樣→預覽→抬筆→權威確認→選取與編修→撤銷→保存。需要逐項記錄壓力／傾斜／速度的支援來源、去重、掌觸與手指分流、縮放旋轉、失焦／斷線與模式切換。

工具可擴充，但筆跡仍由核心持有；Kallopis 不能藉由 painter callback 或樣式參數讓消費端繞過契約。Concepts 的工具列可移動或手勢自訂不自動推翻使用者先前首版固定布局；先盤點再決定產品採用方式。

## Miro 展開規格

逐項表：[Miro 空間元件契約](miro-spatial-components-spec.md)，M01–M24。含物件資格、容器、連線、空間操作及協作接點；專用圖表仍須逐項補齊。

以物件資格與操作能力分離：可編輯、可選取、可移動、可調整尺寸、可容納、可連接可由同物件具備多種資格。逐項記錄錨點、座標、旋轉、範圍、命中、群組、層序、拖放、對齊與鍵盤操作。連線納入完整研究，不再因早期 K10 待定而略過；首版是否啟用與完整元件能力是不同欄位。

同步協作、權限與產品資料來源獨立於通用呈現；不是將 Miro 所有服務搬到本庫。需要服務的元件仍保留資料及事件接點，不以靜態假資料標記完成。

## 統一蒸餾格式

```text
ID / 元件名稱 / 官方來源 / 平台及查證日期
用途 / 資料權威 / 必要輸入 / 合格 slot
可用操作 / 狀態機 / 取消與失敗 / 鍵盤與無障礙
Kallopis semantic / 核心能力 / 產品政策
現有實作 / 缺口 / 排期 / 驗收證據
```

下一步依 N 基本區塊、C 手寫主流程、M 基本物件三份子規格逐項展開；保持一份共同座標、身分、選取、操作與生命週期契約。不同產品功能不等於三套 renderer 或三套風格。
