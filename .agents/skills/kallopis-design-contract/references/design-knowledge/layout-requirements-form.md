# 新布局需求規格表單

新布局任務的第一步是把本表提供給使用者。可保留使用者已明說的答案，但必須請使用者確認；不得從圖片補齊空白欄位。

## 必要欄位

| 分類 | 待填內容 |
|---|---|
| 目標 | 這個布局要完成什麼工作？成功結果是什麼？ |
| 使用者與入口 | 誰使用？從哪個動作或狀態進入？ |
| Screen 邊界 | 新 screen、既有 screen 的區域，還是 overlay？ |
| 內容階層 | 從外到內列出區域、容器、元件與主要內容。 |
| 元件清單 | 每個元件的名稱、責任、必要狀態與可執行動作。 |
| 精確幾何 | viewport、縮放、寬高、padding、gap、對齊、順序、固定或彈性。 |
| 響應規則 | 哪些尺寸會縮放、換行、捲動、收合、移位或消失？臨界條件為何？ |
| 語意 | 每個區域／元件扮演的語意、適用條件、風格結果與採用理由。 |
| 互動生命週期 | 進入、預設、載入、操作、成功、空白、錯誤、復原與離開。 |
| 資料與注入 | 哪些內容固定、由產品提供、由 AI 回傳或由使用者建立？ |
| 參考資料權限 | 每張圖或說明哪些部分是精確規格、哪些只是風格參考、哪些不得沿用？ |
| 無障礙 | 鍵盤順序、焦點、語意標籤、最小操作區與必要對比。 |
| 定型範圍 | 本輪要定型單一元件、局部區域或完整 screen？ |

## 確認結果

| 欄位 | 值 |
|---|---|
| 規格 ID | 待填 |
| 狀態 | proposed |
| 未確定項 | 待填 |
| 使用者確認來源與日期 | 待填 |

必要欄位仍有空白且會產生不同版面結果時，維持 `proposed` 並停止實作。
