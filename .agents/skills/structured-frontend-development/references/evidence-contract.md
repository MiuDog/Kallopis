# 證據契約

## 目的

Evidence bundle 是某一階段、某一次 attempt、某一產物版本的可追溯觀察集合。它用來支持或反駁該階段 gate 的 claims，而不是工作摘要、信心陳述或未來承諾。

## Evidence bundle 的概念欄位

每份 bundle 至少要能辨識：

- 所屬工作流、階段、attempt 與輸入／輸出版本。
- `claim`：要證明或反駁的單一可判定敘述。
- `method`：取得觀察的方式，限定為來源比對、人工檢視、靜態檢查、測試、使用者確認或具同等判定力的方法。
- `observation`：實際看到的結果，不混入推測或結論外延。
- `locator`：他人能重新找到來源、產物位置、對話決策、畫面或命令輸出的精確定位。
- `producer`：產生觀察的人、agent 或工具身分；若由工具產生，亦要能識別工具或命令。
- `timestamp` 或等價的時序資訊，以及被觀察對象的版本。
- `outcome`：此觀察對 claim 是 `pass`、`fail` 或 `blocked`。
- 適用時的限制、環境與重新觀察條件。

## 聚合結果的唯一優先序

Bundle 依下列順序聚合，禁止採用其他優先序：

1. 任一必證 claim 已有充分觀察可判定為 `fail`，整個階段就是 `failed`；同一 bundle 另有 `blocked` 項目也不改變此結果。
2. 沒有任何必證 claim 為 `fail`，但至少一項必證 claim 因外部條件或檢查執行錯誤而無法判定，整個階段就是 `blocked`。
3. 所有必證 claims 均有充分 evidence 且全部為 `pass`，整個階段才是 `passed`。

檢查器故障、服務錯誤、權限不足或環境不可用屬於檢查執行錯誤。它使受影響的必要 claim 成為 `blocked`，不能被記成內容 `fail` 或 `pass`；若同一 attempt 已觀察到其他必要 claim 的內容 `fail`，仍依第一順位將階段聚合為 `failed`，並保留執行錯誤供後續 attempt 處理。非阻斷 findings 必須記錄 disposition，但不改變上述優先序。

## Observed evidence 與 assertion

Observed evidence 必須源自已發生、可定位的觀察，範圍包括真實產物內容、已執行檢查的結果、權威規則原文位置、已顯示的 UI，以及使用者已明確做出的決策。

以下只有 assertion，不能作為 evidence：模型自述「已完成」、計畫執行但尚未執行的命令、沒有 locator 的摘要、依經驗猜測的視覺效果、預期測試會通過、無法連回特定版本的舊結果，以及「看起來應該沒問題」。Assertion 可成為待驗證 claim，但不能開啟下一階段。

## 使用者確認

使用者確認只有在 claim 本質上屬於使用者權限或主觀裁決時才是證據，適用範圍限定為需求取捨、未能由規則裁決的布局選擇、視覺定型、範圍授權及同等的人類決策。紀錄必須包含被確認的具體版本、選項或內容，以及可回到該次確認的 locator。

使用者核准只證明其已做出被記錄的選擇、授權或定型決策，不證明產物或實作已符合該決策。使用者說「繼續」、「可以」或核准計畫，不自動證明程式、視覺、語意或測試正確。能由檢查客觀判定的 claim 也不得要求使用者背書來取代缺少的技術證據。

## 方法與證明力

- 來源證據證明規則確實存在及其適用範圍；它不自動證明實作已遵守。
- 產物檢視證明某版本包含可定位內容；僅有「檔案存在」不能證明內容正確。
- 靜態檢查與測試只支持其實際覆蓋的 claim；必須保存檢查身分、結果與足以判讀的輸出。
- 命令 exit code 0 只證明該命令依其自身條件成功結束，不能單獨證明視覺正確、語意符合、互動可用、需求完整或沒有範圍外變更。
- 視覺或互動 claim 需要能呈現對應狀態與版本的觀察，方法限定為適用的定型比較、可重現畫面檢視、可重現互動檢查、使用者對特定版本的明確確認或具同等判定力的方法。沒有視覺定型時只能回報尚未取得，不得冒稱通過。
- Traceability evidence 必須能從來源 claim 走到產物 locator，也能從產物決策回到來源；僅列出兩份文件名稱不足以證明對應。

## Semantic claim 的充分 evidence

語意符合性 claim 只有同時具備下列四項時才有充分 evidence：

1. 權威語意來源及其 provenance，包含來源 locator、版本或取回時間、適用 scope 與權威層級。
2. 被檢查產物或實作的可定位 observation，包含確切版本、受檢位置與實際觀察內容。
3. 語意來源到受檢位置的 trace／mapping，清楚指出每項來源要求由哪個產物決策或實作位置承擔。
4. 能判定一致或不一致的方法，包含比較準則、檢查範圍與實際判定結果。

只具備來源、只具備產物 observation、只有使用者定型，或只有命令 exit code 0，都不足以證明語意符合。使用者對語意選擇的核准可作為第一項的權威決策來源，但仍必須另有第二至第四項，才能證明實作符合該選擇。

## 不可變性與移交

Evidence 一旦附著於已結束 attempt 就不可改寫。修正內容或重新檢查時建立新 attempt 與新 bundle，保留舊結果。Handoff 時，下一接手者要核對 bundle 是否完整、是否對應目前版本、方法是否足以支持 claims；發現缺口就拒絕接手並將狀態標為 `failed` 或 `blocked`，不得自行補寫觀察。
