# Kallopis：跨框架 Design System 核心目標

日期：2026-10-11。

擁有模組：Kallopis 共通設計規範。

階段：DEFINE；跨框架能力為 0→1，既有 Flutter 元件為抽取與對照來源。

目標版本：核心目標 v1；本階段交付責任與需求定義，不交付框架庫遷移。

狀態：目標與兩項產品選擇已由使用者確認；本階段需求 READY。程式碼尚未依新目標重組。

## 目標

Kallopis 提供一份框架無關的通用視覺規範，涵蓋語意、design token，以及對應語意應使用的通用元件組合與合法限制。各框架元件庫依此規範實作；Flutter、React 等框架庫皆位於 repository 第一層子目錄。

共通規範採用使用者於 2026-10-11 指定的既有 [設計語意統整](../docs/design-tokens/KALLOPIS-DESIGN-MAP.md)，依 [維護規則](../docs/design-tokens/maintenance.md) 按責任分檔；不再重新抽取或定義同一份視覺。框架庫依此規範取得對應值與行為，不能各自建立獨立的共用設計預設。通用規範須整合到既有 docs 網頁，具體整合以維護規則的網站契約為準。

## 責任與公開契約

| 擁有者 | 提供內容 | 邊界 |
| --- | --- | --- |
| 共通設計規範 | 語意用途、token、通用元件角色與組合限制 | 不依賴框架程式型別，不擁有產品資料或流程 |
| 各框架庫 | 該框架的 theme／token 接入、公開元件、組合 API 與互動實作 | 落實共同契約，負責框架及平台差異的明確對應 |
| 產品專案 | 語意與元件選用、畫面組合、資料投影與事件處理 | 遵守共通設計及合法組合，擁有業務與產品狀態 |

框架之間要求語意一致；具體 API、渲染方式與平台互動的對應由後續契約定義。未對應或平台不支援的能力必須明示，不得宣稱已符合。這不授權重建舊 declarative runtime、全產品結構樹驗證或私有 renderer 使用入口。

## 現行來源與取代範圍

- 本文件定義新核心目標，取代「Kallopis 永久只提供 Flutter design system」的專案定位。
- [KLP-0022](decisions/KLP-0022-thin-design-system-boundary.md) 仍描述目前已完成的 Flutter 使用路徑；其中產品擁有畫面與流程、移除 declarative runtime、私有實作不對 consumer 開放等邊界繼續有效。其 Flutter 公開入口不套用到其他框架。
- [既有風格](style-v1.md) 與直接相關的已確認修訂，是視覺抽取依據；歷史 renderer／bound 等實作描述不能直接成為新跨框架契約。
- [設計語意統整](../docs/design-tokens/KALLOPIS-DESIGN-MAP.md) 已由使用者指定採用為正式通用規範；[JSON／CSS 與 theme 欄位匯出](../docs/design-tokens/README.md) 仍是來源快照，不構成另一份設計權威。
- Krepis／provider 的正文與保存權威、產品編輯器宿主所有權不因本目標改變。
