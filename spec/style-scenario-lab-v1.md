# React 可採用情境 Examples v1

擁有模組：React example 情境與風格展示。階段：Iteration（既有展示的風格驗證、探索與消費端採用）。
Readiness：READY。使用者於 2026-10-16 確認先採 React，並明確要求建立本專案 example，方便消費端直接採用。首輪以研究資料庫作為可逆的情境選擇，其餘逐次擴展。本文件完成 DEFINE；未建立新畫面或修改共用庫。

## 目標與邊界

在本專案 `react/example/` 建立可直接採用的情境範例，使用 Kallopis 公開元件，讓消費端可閱讀、複製或組合範例原始碼，替換資料與事件後建立自己的畫面。同時讓使用者在可操作的畫面中驗證風格使用正確性、不同情境的適應能力與實驗風格。

情境是 example 層的虛構資料與互動，不提升為共用庫的產品業務元件，不規定消費端的業務功能或順序。情境畫面可獨立於展示導覽及風格調整工具採用；不要求消費端複製整個 example 應用。

正式視覺依據為 [通用規範](../docs/design-tokens/KALLOPIS-DESIGN-MAP.md)。實驗風格不覆寫正式基準；變體名稱不代表已接受的品牌方向。保留 icon 按鈕列、參數 row、hover／selected 同色與 package 字型 ownership。

## 情境提案

| 情境 | 可操作核心流程 | 主要觀察 |
| --- | --- | --- |
| 研究資料庫 | 搜尋資料、選取項目、閱讀摘要、修改本地備註 | Explorer、閱讀層級、長中英混排、空搜尋結果 |
| 營運處理台 | 篩選案件、選取案件、調整處理狀態 | 密集資訊、狀態語意、disabled、長名稱與大量清單 |
| 內容策展台 | 選取作品、預覽內容、調整屬性 | 預覽與工具區的主次、表面層次、參數 row |
| 個人規劃頁 | 切換分組、完成項目、編輯項目詳情 | 低密度資訊、表單焦點、空狀態、窄視窗 |

第一個完整情境為研究資料庫；其餘為後續迭代目錄，不一次建立全部業務流程。

## 風格探索提案

- Kallopis 基準：保持正式來源，作為每次對照起點。
- 緊湊工具風：探索較密集控制與間距，觀察資訊量與辨識性；使用合法覆寫。
- 舒展閱讀風：探索較寬鬆間距與文字層級，觀察長文與低密度頁面。
- 冷調平面風：探索中性色溫與表面效果變化，觀察是否仍保有清楚層級及互動狀態。

明暗 mode 與上述變體分開比較。每次迭代只改一組相關參數，記錄變更與受影響情境；不將布局變更混入純風格比較。

## 現有入口與介面

React 已有 `react/example/modern-productivity-preview.tsx` 的 provider、合法覆寫、還原與複製設定流程；`react/example/scenario-registry.mjs` 已登錄三個工作區情境。可作為後續 PLAN 的現況證據，並不要求複製現有實作。

Style pack 輸入及錯誤以公開框架 API 為準；正式數值仍依 Markdown 權威。`styles/README.md` 的框架進度敘述與已觀察的 React preview 不一致，不能只憑該文件斷言框架尚不支援注入。此草案不改動來源權威或修訂既有文件。

Example 擁有虛構情境資料、示範事件處理與畫面暫態；採用後由消費端擁有產品資料與業務副作用。框架庫擁有元件行為與風格解析。風格由既有公開 provider 接入，情境不另建預設 theme。設定無效時提供錯誤與保留上一份有效畫面；缺少公開能力時明示缺件。

## 驗收與能力地平線

首輪交付一個完整 React 情境、消費端採用說明、基準與實驗變體比較、可重現設定與觀察紀錄。採用說明必須列出範例責任、必要檔案、資料與事件入口、theme／資產需求與最小組合方式。後續逐一擴展情境；Flutter 不在首輪交付範圍。

程式證據只涵蓋公開 API 使用、設定合法性、狀態保留、實際操作與渲染觀察。視覺品質、易讀性、風格適用與手感由使用者評判。每個問題記錄情境、風格、狀態、重現條件與判斷；未觀察不得記為通過。

無後端、真實帳號、遠端資料、發布或正式設計規範變更。本輪沒有執行 BUILD、測試或畫面驗收。
