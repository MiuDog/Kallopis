# Explorer：資料、行為與視覺分離

階段：DEFINE／Iteration。狀態：READY。目標版本：Explorer 契約 v1，含 2026-09-15 箭頭與後代收合修訂（修訂已完成 PLAN／BUILD，EXP-V1-r3 Catalog 已由使用者接受）。

使用者已接受 A～F、H 的建議；G 明確選擇移除舊 Explorer，直接替換並同步遷移受影響 consumer。本規格可交付 PLAN；不代表程式或新外觀已完成。

語意擁有者：Kallopis 通用 Explorer 功能，位於既有 features 責任範圍。本頁不決定實體模組拆分、Dart 型別名稱或 Task Packet。

上位邊界：[視覺元件統一維護](visual-component-governance.md)。Kallopis 擁有通用視覺及合法組裝規則；consumer 擁有產品資料、行為選擇及使用者設計的組合邏輯。Planist 組裝真相留在 [Planist 規格](../../Planist/docs/planning/sidebar-composition.md)，不建立本庫產品專用元件。

## A／B：組裝與最小 interface 語意

- 每個 item 有穩定的出現身分、標題、分類／節點角色、完整有序 children，以及對應的有限能力。產品資料 ID 可另由 consumer 保存；同一資料出現於不同位置時使用不同出現身分。
- 子項承載能力由 consumer 節點類型固定定義；hasChildren 只投影當前 children，不代替能力。
- 不可承載的類型卻提供子項時拒絕；可承載且當前無子項合法。資料樹無產品層任意深度上限，循環仍拒絕。
- 分類與節點使用相同能力詞義。結構資格限制不推導為不可選取、不可啟用或必須收合。
- 同一份資料樹是階層來源。列或操作插槽不得另提供一份不同的子項順序，也不允許將同一出現身分重複掛載以形成第二份階層。
- Consumer 可選擇 KLP 合法部件及插槽內容；列內已存在元素的順序、對齊、尺寸、間距與命中規則由 KLP 維護。分類一律顯示箭頭；一般節點僅在可收合且有子項時顯示。箭頭可否操作仍依收合能力，不由 consumer 畫箭頭或因分類角色覆蓋能力。
- 行內操作與內容選單為獨立、明確的呈現選擇；可只有內容選單，不默認加「更多」按鈕。Consumer 選擇具名操作入口及命令資料，不能自訂選單 renderer。
- 主標題、可選圖示、附註／徽章及操作是本輪列內容範圍；任意輸入欄、任意富內容及自訂布局不因 item interface 而隱式開放。新增需求仍可回到本庫 DEFINE。

## C／D：能力、狀態及事件

- Consumer 擁有唯一且完整的 selected／expanded 狀態及事件處理；KLP 維護 hover、pressed、焦點、暫開選單與拖曳預覽等暫態互動，不持久化產品狀態。
- 選取範圍是明確的互動契約，不是 Explorer 容器的資料承載開關，也不改各節點類型的能力。單一 selection 狀態表示成一份集合與模式，不再以 selectedId／selectedIds 的隱式優先序競爭。
- 預設範圍為一棵明確宣告的樹；共用選取須由 consumer 明確指定共享狀態及成員範圍。跨多個顯示區的多選必須有確定的可見順序，不能靠各 renderer 私有 anchor 推測。
- 指標普通點擊只在 item 可選取時提出選取變更，再執行 consumer 指定的標題主動作；主動作為無時只選取。多選範圍的 Ctrl／Meta 切換及 Shift 可見連續範圍只改選取，不啟用產品內容。不可選取項不進入範圍集合。
- KLP 不知道「開啟頁面」：啟用只是一次語意事件。Consumer 決定是否導航、顯示 popup 或執行產品操作。Enter 執行焦點列的主動作；上下鍵移動可見列焦點，左右鍵按樹關係展開／收合或移到父／子列，不自行導航產品。
- 展開箭頭只送展開請求，不連帶選取或啟用；內容選單只提出命令，不靜默改選取。空分類仍顯示箭頭且在可收合時可操作；空的一般節點不顯示可展開控制。不可收合的分類保留展開方向指示但不發出切換請求；不可收合但有子項時保持子內容可見。
- 標題策略選擇切換展開時，item 須允許收合；否則拒絕矛盾宣告。合法但當前沒有子項的一般節點不發出展開請求；可收合的空分類可透過既有切換入口改變展開狀態。
- 產品選擇保留後代展開狀態或遞迴收合後代，適用於分類與節點的所有收合入口。遞迴模式清除該子樹所有可收合後代的展開狀態，包含原先已隱藏的後代；不可收合項的能力不被覆蓋。重新展開只展開本項，不自動展開後代。Consumer 仍擁有唯一展開狀態，須同批提交完整更新；未提交或提交失敗時保留上一份已確認狀態。
- 通用 Explorer 未選擇遞迴模式時沿用保留後代狀態的行為；Planist 在產品端預設選擇遞迴收合。此設定不提供逐節點覆寫或新增終端使用者設定畫面；公開 API 及事件承載方式交由 PLAN 決定。
- 選取／展開、移動或命令發出後，KLP 等待 consumer 提供下一份已確認狀態或資料，不自行提交另一份樹。Consumer 未更新則保持已確認狀態；只反映本次按壓等暫態。
- 狀態中不存在的出現身分、不可選取項被 selected、不可收合項或無子項的一般節點卻宣告 expanded，視為不一致輸入；可收合空分類允許 expanded。Consumer 應同批提供一致資料與狀態；整份更新拒絕，保留上次有效畫面並回報明確契約錯誤，不靜默修補。
- 輸入沒有錯誤不代表業務操作必然成功；產品操作的取消／失敗留在 consumer，錯誤回報使用既有應用錯誤權威。

## E：拖放與通用命令

- KLP 將手勢轉為來源出現身分集合、目標出現身分與 before／inside／after。分類也可由 consumer 宣告是否可拖動；是否允許放置須同時符合 A 的角色結構及 consumer 許可。例如分類可以在樹根重新排序，但本輪不能拖入另一分類或節點之下。
- Node 類型可承載子項只是 inside 的必要條件，不是移動權限。Consumer 的許可處理缺席即拒絕；提交前再驗證當前許可，不用先前 hover 的許可作授權。
- KLP 拒絕可由輸入樹判定的自我／後代循環及無效目標。跨專案權限、移動與引用差異、資料保存及恢復均由 consumer 決定。
- 通用命令以同一份資料供行內入口、右鍵、鍵盤選單使用。滑鼠選單依觸發位置、鍵盤選單依焦點列定位；行內按鈕依其錨點定位，均受 viewport 邊界約束。
- 輸入／確認由 KLP 的通用能力呈現，選項與文案由 consumer 提供；命令是否需要輸入或確認必須明確宣告，不由標籤或產品型別推測。
- 命令結果可區分完成、取消與失敗；不代替產品提交。確認前不執行業務動作，取消不發出提交；失敗可回報且保留原資料，重試由 consumer 控制。
- 功能模組不各自內嵌不同的命令樣式、文字輸入或確認表面；本輪須整合至共用呈現責任，具體型別與檔案歸屬由 PLAN 配對。

## F：風格與 Catalog 接受

- 色調、字型來源及已接受共用風格沿用 [風格 v1](style-v1.md) 與 [8px／微立體](frame-relief-8px.md) 的適用條款；不藉此將所有 Explorer 間距設成 8px 或擅自統一所有圓角。
- Explorer 普通背景透明，露出 KLP 宿主表面；selected／hover／focus 等按各自用途顯示。需要獨立表面時由 consumer 在合法位置選用本庫表面元件，不傳顏色。
- 分類列高、節點列高、圖示、字級、縮排、內容內距及命中尺寸分別有語意用途。合理的幾何包含關係可連動；內距與字級等無因果關係的值不得用相減湊出。
- Catalog 先展示角色／能力／合法組合與實際宿主表面，再呈現正常、選取、焦點、展開／收合、空子項、長文字、多層節點及命令表面等適用狀態。
- 支援的桌面鍵盤／滑鼠先驗收；其他平台沿用既有能力但不以桌面圖宣稱已接受其特定交互。明確改變平台行為時需在相應候選中展示。
- 人類接受外觀；確定性的型別、幾何、事件、選取範圍與生命週期由程式證據驗收。概念圖不能冒充真實 renderer 已通過。
- 本輪進入 PLAN 前接受的是外觀基調、維護責任及 Catalog 驗收方式，不是尚未展示的具體新外觀。視覺實作切片須在相應 Catalog 候選接受後才固定外觀；基礎資料與契約切片不偷渡未接受的視覺值。

## G／H：交付、相容與排除範圍

- 本輪交付產品無關的完整 Explorer 能力及「如何宣告 → 如何組裝」文件，功能名稱沿用 Explorer 概念，公開型別名稱由 PLAN 定案。
- 文件涵蓋 interface 欄位、consumer method 包裝、角色／插槽、能力矩陣、狀態／事件、合法及拒絕案例、Catalog 與遷移指南；原始碼或孤立範例不能代替完整契約。
- 直接移除被替換的舊 Explorer API 與專用實作；不建立過渡相容入口或第二套呈現。PLAN 必須盤點公開可達面、直接與間接使用者、Catalog、文件及契約檢查，配對必要呼叫端遷移；交付不保留懸空舊呼叫。具體刪除檔案與共用檔案保留邊界由 PLAN 指定，不能整檔刪除其他功能。
- 受影響的 Planist 呼叫端同批完成必要 API 接線，仍按 Planist 的使用者設計與產品契約執行；這不授權順便重寫商業流程或進行 folder→頁面樹的持久化資料遷移。
- 不藉本輪刪除所有 Stable API，不修改持久化資料格式。Planist 的 folder→頁面樹資料遷移仍由產品規格及產品 owner 負責。
- 通用元件的選取範圍、分類角色或命令介面不能包含「專案／待辦／資產／收藏」等產品特例。
- 子項延遲載入、任意 Widget／painter、產品專用元件及不相關 feature 全面遷移不在本輪。
